# Built with Agents

A public log of projects I've built alongside AI agents — what they are, how I worked with the tools, and what I'd do differently. The "AI workflow" section on each case study is the part actually worth reading.

See [`MVP.md`](./MVP.md) for the original spec.

## Stack

- Astro 5 (static output, Content Collections)
- Tailwind CSS v4 (via `@tailwindcss/vite`)
- TypeScript strict
- MDX for case studies
- React islands only where interactivity is genuinely needed (`VideoEmbed`, `CopyLinkButton`)
- Self-hosted Inter + JetBrains Mono (no third-party font CDN)
- Vercel deploy + Vercel Analytics

## Local dev

Requires Node 20+ and pnpm.

```bash
pnpm install
pnpm dev          # http://localhost:4321
pnpm build        # produces dist/
pnpm preview      # serves dist/ locally
```

## Authoring a project

Each case study is one MDX file under `src/content/projects/<slug>.mdx`. The route is `/projects/<slug>`.

### Frontmatter schema

Validated by `src/content.config.ts`. Mirrors the spec in `MVP.md`.

```yaml
title: string
oneLiner: string
status: 'live' | 'archived' | 'wip'
year: number
role: 'solo' | 'lead' | 'contributor'
stack: string[]
aiTools: string[]                   # e.g. 'Claude Code', 'Cursor'
links:                              # omit any field you don't have a real URL for
  github: string                    # optional
  publicUrl: string                 # optional
  video: string                     # optional — Loom or YouTube; renders embed when present
heroImage:                          # optional
  src: ./relative/path/to/image.png
  alt: string
order: number                       # sort key on landing
featured: boolean                   # one project gets the featured slot
```

### Required body sections

The MDX body must include these five `##` headings, in order:

1. The problem
2. **AI workflow** — the section worth reading. Don't skip; don't stub.
3. Architecture
4. Outcomes
5. What I'd do differently

### Conventions

- Don't fabricate links or descriptions. If you don't have a real URL, omit the field — `LinkBar` only renders buttons for present links.
- One project at a time, real prose only. Placeholder text is fine while drafting; ship real content before flipping `status: 'wip'` to `'live'`.
- For video embeds, paste a Loom or YouTube URL into `links.video`. The page lazy-loads the iframe and locks aspect ratio for CLS = 0.

## Design tokens

Defined as Tailwind v4 `@theme` variables in `src/styles/global.css`. The accent is a deep, restrained green (`#15803d` light / `#4ade80` dark). Dark mode follows `prefers-color-scheme` — there's no toggle in the MVP.

## Deploy (Vercel — recommended)

The default config uses `@astrojs/vercel` and Vercel Analytics.

1. Push the repo to GitHub.
2. In Vercel: **New Project** → import the repo. Vercel auto-detects Astro; build command `pnpm build`, output handled by the adapter.
3. Set the production domain in **Settings → Domains**. Update `site` in `astro.config.mjs` to the canonical URL so absolute OG image URLs resolve.
4. Vercel Analytics is enabled in the adapter config — no extra steps.

## Deploy (Cloudflare Pages — alternative)

Swap the adapter:

```bash
pnpm remove @astrojs/vercel @vercel/analytics
pnpm add @astrojs/cloudflare
```

In `astro.config.mjs`:

```js
import cloudflare from '@astrojs/cloudflare';
// ...
adapter: cloudflare(),
```

In Cloudflare Pages: build command `pnpm build`, output directory `dist/`. For analytics, use Cloudflare Web Analytics (no cookie banner required).
